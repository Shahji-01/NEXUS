# NEXUS — Full Deployment Guide (Vercel + Render, free tier)

This is the complete, step-by-step guide to deploy NEXUS:

- **Frontend (React dashboard)** → **Vercel** (static, free)
- **Backend (Express API + WebSocket)** → **Render** (free web service)
- **Database (PostgreSQL)** → **Render** (free)

```
  Browser ──▶ Vercel (dashboard)  ──HTTPS / WSS──▶  Render (API)  ──▶  Render Postgres
              env: VITE_API_URL ───────────────────▶ https://<api>.onrender.com
```

> The Python CV detector is **not** deployed on the free tier (PyTorch/YOLO need
> far more than Render's 512 MB). The app runs in **simulation mode** and video
> mode falls back gracefully. See [Step 6](#step-6--optional-enable-video-detection)
> to enable it on a paid host.

---

## Step 0 — Security checklist (already verified)

Before pushing, confirm nothing sensitive is committed. These are already
handled in this repo:

- ✅ `.env` (your real secrets) is git-ignored — **never commit it**.
- ✅ `.env.example` (placeholders only) **is** committed as the template.
- ✅ Model weights (`*.pt`) and demo clips (`apps/detector/clips/*.mp4`) are
  git-ignored (large; not needed in git).
- ✅ `node_modules/`, `dist/`, `*.tsbuildinfo`, `__pycache__/` are git-ignored.
- ✅ No API keys / tokens / private keys exist in tracked source.

Quick re-check before you push:

```bash
git status                 # .env must NOT appear
git check-ignore .env      # should print ".env"
git ls-files | grep -i env # should only show .env.example
```

Secrets are provided at deploy time as **environment variables** on Render/Vercel
— not files.

## Step 2 — Deploy the backend on Render (do this first)

The frontend needs the backend URL, so deploy Render first.

1. Go to <https://dashboard.render.com> → **New** → **Blueprint**.
2. Connect your GitHub repo. Render detects [`render.yaml`](./render.yaml) and
   shows two resources to create:
   - `nexus-db` — free PostgreSQL (database `nexus`)
   - `nexus-api` — the Node web service
3. Click **Apply**. Render then automatically:
   - injects `DATABASE_URL` from `nexus-db`,
   - generates `SESSION_SECRET`,
   - runs the build: `pnpm install → build the API → push the Drizzle schema`,
   - starts the API (it reads Render's `PORT`),
   - health-checks `GET /api/healthz`.
4. (Optional) On the `nexus-api` service → **Environment**, set `GEMINI_API_KEY`
   to enable the AI Copilot.
5. When live, copy the URL, e.g. `https://nexus-api.onrender.com`.

**Verify:** open `https://<api>.onrender.com/api/healthz` → `{"status":"ok"}`.

---

## Step 3 — Deploy the frontend on Vercel

1. Go to <https://vercel.com/new> and import the **same** GitHub repo.
2. Vercel reads [`vercel.json`](./vercel.json) automatically (build command,
   output dir `apps/web/dist/public`, SPA rewrites). Keep the **Root Directory**
   as the repository root.
3. Open **Environment Variables** and add (for **Production** and **Preview**):

   | Name           | Value                                |
   |----------------|--------------------------------------|
   | `VITE_API_URL` | `https://nexus-api.onrender.com`     |

   Use your real Render URL — **no trailing slash, no `/api`**. This is compiled
   into the bundle at build time and is used for both REST and the WebSocket.
4. Click **Deploy**. When done, open the Vercel URL — the dashboard loads and
   connects to the Render API.

> ⚠️ `VITE_API_URL` is baked in at build time. If you change it later, you must
> **redeploy** on Vercel.

---

## Step 4 — Verify end to end

On the live Vercel URL:

- The dashboard loads and shows live (simulated) lane data and signals.
- Browser DevTools → Network: REST calls go to `https://<api>.onrender.com/api/...`
  and a WebSocket connects to `wss://<api>.onrender.com/api/ws`.
- The **Data Source** toggle stays on **Simulation** (video needs the detector).

## Step 5 — Environment variables reference

| Service | Variable | Required | Source |
|---------|----------|----------|--------|
| Render `nexus-api` | `DATABASE_URL` | yes | auto from `nexus-db` |
| Render `nexus-api` | `SESSION_SECRET` | yes | auto-generated by Render |
| Render `nexus-api` | `PORT` | yes | provided by Render |
| Render `nexus-api` | `DETECTOR_URL` | no | empty → simulation fallback |
| Render `nexus-api` | `GEMINI_API_KEY` | no | you set it (enables Copilot) |
| Vercel | `VITE_API_URL` | yes | the Render API URL |

## Step 6 — (Optional) Enable video detection

Free Render can't run the detector. To enable live CV detection:

1. In [`render.yaml`](./render.yaml), uncomment the `nexus-detector` service
   (Docker runtime, paid `standard` plan, uses `apps/detector/Dockerfile` which
   installs **CPU** PyTorch + YOLO).
2. Provide the four `lane_{0..3}.mp4` clips to the detector (bake into the image
   or attach a Render disk — they're git-ignored by design).
3. Set `DETECTOR_URL` on `nexus-api` to the detector's URL and redeploy.
4. The dashboard's Data Source toggle now drives live detection.

For local/self-hosted full stack (API + detector + DB) use
[`docker-compose.yml`](./docker-compose.yml) — see [`DEPLOY.md`](./DEPLOY.md).

## Troubleshooting

| Symptom | Cause / Fix |
|---------|-------------|
| First load is slow (~30–60 s) | Render free tier sleeps after ~15 min idle; it cold-starts on the next request. Normal. |
| Dashboard shows no data | Check `VITE_API_URL` is set on Vercel and you **redeployed** after setting it. |
| API calls blocked by CORS | The API allows all origins by default; confirm `VITE_API_URL` points at the correct Render URL (https). |
| WebSocket won't connect | It derives `wss://` from `VITE_API_URL`; ensure that's the `https://` Render URL. The app polls as a fallback. |
| Render build fails on `pnpm` | The repo pins `packageManager: pnpm@10.32.1`; the build runs `corepack enable` first. |
| DB tables missing | The build runs `pnpm --filter @workspace/db run push`; re-deploy to re-apply. |
| Free DB stopped working | Render free Postgres expires after 90 days — recreate it. |

## Security note (before any non-demo use)

The included auth is a **demo**: a hardcoded `admin` credential with client-side
gating only, and the mutating endpoints (`/api/signals/*`, `/api/source/mode`)
are **not** server-authenticated. Add real authentication/authorization before
exposing this publicly. Render (HTTPS/WSS) and Vercel (HTTPS) provide TLS by
default.
